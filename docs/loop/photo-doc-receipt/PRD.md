# PRD — 📄 文件拍照助手＋🧾 收據拍照記帳（共用影像管線）

## 背景
越南家人拍照片目前只會得到「描述」。兩個真實痛點：
1. 帳單/公文/藥袋/學校通知看不懂——要「這是什麼、要做什麼、期限幾號」，有期限最好能一鍵設提醒。
2. 收據記帳要手動打字——拍照就該能一鍵記入家庭帳本。

## 技術前提（已探明）
- LINE 圖片內容約 60 秒過期 → 不可「先問用途再抓圖」。
- 現行 `handleImage`：抓 buffer → `ai.vision(buf,'image/jpeg', lang.visionPrompt(code))` → 描述進對話記憶 → 回字串。
- 回覆管線支援 `{text, quickReply}`；pending 模式已有 traChoice/gasStation 前例。

## 需求
### F1 文件助手
- 拍「文件類」（帳單/公文/藥袋/通知/合約）→ 回覆結構化說明（類型/重點/該做什麼/期限/金額），用使用者語言。
- 有可用期限 → 附一顆 `⏰ 設提醒` Quick Reply；點了 → 建一次性提醒（**期限前一天 09:00**；不行則期限當天 09:00；都過去→不給按鈕）。提醒訊息＝模型抽的行動標題（如「繳電費」）。
- 民國年（如 115/07/15）需正確 +1911 轉西元。

### F2 收據記帳
- 拍收據/發票 → 描述＋摘要（店名/總額）→ 附 `✅ 記帳 {金額}元` 確認按鈕（**先確認再記**，不自動寫入——家庭共用帳本不可被誤辨識污染）。
- 點確認 → 記入帳本、回「已記帳＋本月累計」＋ `↩️ 撤銷` 按鈕；點撤銷 → 移除該筆並回還原後累計。
- `撤銷記帳`（vi: hoàn tác）文字指令＝過期後備（只撤 10 分鐘內自己最新一筆，否則回「沒有可撤銷的」）。

### 共通
- **單次 vision 呼叫**完成描述＋分類＋抽取（enriched prompt＋結尾 `##TAG {json}` 機器標籤）；
  標籤解析失敗/缺漏 → 一律當一般照片（**與現行行為逐字相同**），絕不報錯、標籤絕不外漏。
- **按鈕文字＝真實指令**（`記帳 <店名> <金額>`、`提醒我 <datetime> <標題>`、`撤銷記帳`）：
  pending（3 分 TTL、每人一筆）過期或重啟後點舊按鈕，仍走既有文字路由成功執行。
- 隱私：文件內容只進 RAM 對話記憶；落地僅限使用者按過確認的 `{品項,金額}`/提醒標題；`##TAG` 不進記憶不落地。
- 店名清洗：去數字（防 `7-11` 被記帳路由的取數 regex 誤抓）、≤10 字、空→「收據」。

## 驗收（可測，全離線 stub）
1. `parseVisionTag` fixture 矩陣 ≥14 組（乾淨收據/文件標籤、fence 包裹、標籤在文中、無標籤、JSON 截斷、
   金額 0/負/1e10、期限 2026-13-40/民國未轉/過去日、store 200 字、只有標籤沒描述）：永不 throw、
   回傳文字永不含 `##TAG`、無效→`{type:'other'}`。
2. `computeRemindAt`：期限 10 天後→前一天 09:00；期限明天且現在 22:00→當天 09:00；期限今天且已過 09:00→null；3 年後→null。
3. `handleImage`（stub vision）：receipt fixture→`{text,quickReply}` 恰 1 顆訊息按鈕、label≤20；document→提醒按鈕；other→回傳字串與現行行為一致；vision 回空→imageUnclear。
4. tap 矩陣（zh＋vi）：確認→記入含 id、累計正確、附撤銷鈕；撤銷→移除、累計還原；**pending 過期（回撥 ts）→ 點舊按鈕走 `記帳` 文字路由仍成功**（含 `7-11` 清洗）；連點確認兩下→第二下走文字路由（不經 pending 重複攔截）；提醒 tap→reminders.json 出現正確 datetime 的 once 項。
5. 並存：與 traChoice pending 同時存在互不誤觸（tap 文字命名空間互斥斷言）。
6. 隱私掃描：文件 fixture 獨特字串不出現在 data/*.json（除確認後品項/金額）；conversation 無 `##TAG`。
7. 回歸：一般照片、「記帳 午餐 120」、「提醒我…」等既有路由不變；node --check 全過。
