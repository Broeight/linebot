# FIX — 三視角驗證（邊界獵人）發現的修正

三視角平行驗證結果：獨立測試員 PASS（89 檢查）、審查員 PASS、邊界獵人 162 項攻擊守住其餘全部，
但逮到 1 個 major＋1 個值得修的 minor，皆已修正並重驗（13/13）。

## Major：normHM 放行 25:00 → 無聲死提醒

`normHM()` 原本只驗格式 `/^(\d{1,2}):(\d{2})$/`，不驗時分範圍。若 AI 解析吐出 `25:00`／`99:99`
這類非法時刻，bot 會回「✅ 已設定 每週一 25:00」並存檔，但 `tick()` 比對 `r.time === now.hm`
（上限 23:59）永遠比不中——**確認成功卻永遠不響**，是提醒功能最糟的無聲失敗（繳房租類直接漏）。

**修法**（reminder.js，一行）：`normHM` 加範圍檢查 `+m[1] > 23 || +m[2] > 59 → null`。
效果：weekly/monthly 收到壞時刻 → 落 `|| '09:00'` 預設（與 DESIGN §5「缺/壞 → 09:00」意圖一致）；
daily（addParsed 路徑）→ `{ok:false}` 請模型重問。邊界值 23:59／00:00 仍合法。

註：`add()` 關鍵字路徑的 daily 分支用獨立 regex `/^\d{2}:\d{2}$/`（pre-existing，不在本輪
新增面），同類風險留待日後提醒多語化輪一併處理。

## Minor：「刪除提醒3」（無空白）漏進 AI 聊天

原 route `/^刪除提醒\s+(.+)$/` 要求至少一個空白；長輩打「刪除提醒3」會三條提醒 route 全不命中、
落入 AI 對話 fallback（AI 無刪除工具，回覆不可預期）。

**修法**（handler.js）：`\s+` → `\s*`。裸字「刪除提醒」因 `(.+)` 需至少一字仍不命中、
照舊落到精確比對走全刪（不回歸，已重驗）。

## 重驗結果（scratchpad 腳本，13/13 PASS）

- weekly `25:00` → `every Monday 09:00`；monthly `99:99` → `09:00`；daily `25:00` → `{ok:false}`
- 正常值不受影響（`19:00`、`8:30`→`08:30`）；邊界 `23:59`／`00:00` 合法
- `刪除提醒1`（無空白）正確刪單筆；`刪除提醒 1`（有空白）不變；裸字仍全刪；`刪除提醒abc` 回引導句
- data/ 備份還原逐字驗證 OK
