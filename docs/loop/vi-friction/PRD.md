# PRD — 越南語無障礙第 1 輪：不再出現看不懂的訊息 + 越南語選單/直達

## 背景（真實證據）
越南家人（陳氏梅）2026-07-01 連問三次火車失敗後，收到的最後一句是**中文**
「抱歉，我現在無法回覆，請稍後再試。」（出處 `src/ai.js:114` 寫死字串）。
盤點後發現所有「錯誤/引導/結果標題」類訊息都是寫死中文，對看不懂中文的使用者
等於沒有回覆。另外 `/help` 選單 100% 中文，她無從得知 bot 有哪些功能。

## 目標
1. **她再也不會收到看不懂的訊息**：所有錯誤與提示依使用者語言輸出（沿用 lang.js 六語表機制）。
2. **她能發現並直達功能**：越南語選單（trợ giúp）+ 常用越南語關鍵字直達。

## 範圍（要做）

### F1 錯誤訊息本地化（P0）
把以下寫死中文改為依使用者語言（lang.js 新表 + getter；zh-TW 文案維持原句不變）：
| # | 現況位置 | 原句 |
|---|---|---|
| 1 | `ai.js:114`（chat 失敗 fallback） | 抱歉，我現在無法回覆，請稍後再試。 |
| 2 | `index.js:64`（總 catch） | 抱歉，發生了一點問題，請稍後再試 🙏 |
| 3 | `handler.js` handleAudio 抓取失敗 | 抱歉，我拿不到這段語音 🙏 |
| 4 | `handler.js` handleAudio 聽不清 | 我聽不太清楚，可以再說一次、或直接打字給我嗎？ |
| 5 | `handler.js` handleImage 抓取失敗 | 抱歉，我拿不到這張圖片 🙏 |
| 6 | `handler.js` handleImage 看不懂 | 我看不太懂這張圖，換一張清楚一點的試試？ |

注意：`ai.chat` 不知道使用者語言 → 由呼叫端（handler）把該語言的 fallback 傳進去
（`ai.chat` 增加選項參數，預設維持原中文句，不破壞其他呼叫者）。
`index.js` 總 catch 從 `event.source.userId` 盡力解析語言，失敗就用中文。

### F2 台鐵「點按鈕後結果」本地化（P0，接續 PR #2 的 v1 限制）
`getTraTrainByIds`（pending 完成查詢、她點按鈕後看到的）目前回中文格式。改為：
- 增加選用參數 `code`（語言碼），handler 傳入。
- **標題行**（🚆 台鐵 X → Y）、**「今日已無班次」**、**行駛時間單位**依語言輸出
  （vi 例：`X giờ Y phút`、無班次 `Không còn chuyến tàu nào hôm nay/ngày mai.`）。
- 班次行的車次/車種/時刻維持原樣（數字與中文車種名可讀）。zh-TW 輸出與現況完全相同（不回歸）。

### F3 越南語功能選單（P1）
- `helpText` 改為 `helpText(code)`：zh-TW 用現有全文；**vi 提供完整越南語翻譯版**；
  en 提供英文版；ja/th/id 回落到 en。
- 觸發字新增：`trợ giúp`、`giúp đỡ`、`menu`、`hướng dẫn`（不分大小寫）→ 回該使用者語言的選單。
- 既有中文觸發字（/help、說明、選單）行為不變，但**回覆語言依使用者語言**（中文使用者仍看中文）。

### F4 越南語關鍵字直達（P1，只做高價值、確定性的）
在 AI fallback 之前新增路由（不分大小寫、容忍前後空白）：
- `giá xăng` / `giá dầu` → `fuelPrice.lookup()`（全部油品）
- `tỷ giá`（後面沒接東西）→ 匯率 **TWD→VND 預設**（她的主場景）；
  `tỷ giá` 後接內容 → 原樣丟給 `exchangeRate.lookup`（已支援 TWD/VND 等代碼）。
- 不做 `thời tiết`/`tàu`（需要地名/站名參數，AI 路徑處理得更好，避免半吊子直達）。

### F5 加油站距離單位（小加分，本分支疊在 PR #3 上可直接改）
`gasStation.formatList` 的「公尺/公里」改為中性 `m` / `km`（各語言通用），
或依語言輸出（zh 維持 公尺/公里）。擇一，架構上取簡單者。

## 不做（範圍外）
- Rich Menu 圖形選單（第 2 輪閉環）。
- 早安推播、喝水提醒、/reset 確認等「中文關鍵字才會觸發」的訊息（使用者會中文才觸發得了，暫緩）。
- 台鐵班次「全文」翻譯（多一次 AI 呼叫，之後做成可選）。
- TTS 語音回覆。

## 驗收條件（可測）
1. **六語表完整**：新增的每個 lang getter 對 zh-TW/vi/en/ja/th/id 都回非空字串；vi 版含越南語字元；未知碼回落 zh-TW。
2. **zh 不回歸**：zh-TW 使用者收到的上述每一句話與改版前**逐字相同**（含 emoji）。
3. **ai.chat fallback**：模擬 Groq 全掛（或注入 fallback 參數）→ handler 對 lang=vi 的使用者回越南語 fallback；
   未傳參數的 `ai.chat` 呼叫回原中文句（相容性）。
4. **台鐵按鈕結果**：`getTraTrainByIds({...code:'vi'})` 輸出含越南語標題/單位；`code:'zh-TW'` 或不傳 → 與現況逐字相同。
5. **選單**：`handleText(vi使用者, 'trợ giúp')` → 越南語選單（含 trạm xăng／tàu 等字樣）；
   `handleText(中文使用者, '選單')` → 現有中文選單原文。
6. **直達**：`giá xăng` → 中油油價字串（不經 AI）；`tỷ giá` → TWD/VND 匯率字串（不經 AI）。
7. **距離單位**：`formatList` 對 vi 使用者輸出不含「公尺/公里」（用 m/km 或越南語）。
8. `node --check` 全變更檔通過；既有功能（台鐵中文指令、加油站、天氣、聊天）不回歸。
