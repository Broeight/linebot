# PRD — AI 回答前先上網收集資料（聯網搜尋）

## 背景
目前 AI 對話只靠模型內建知識（訓練截止後的事不知道、細節可能記錯）。
家人問「最近的新聞」「某產品多少錢」「某藥的資訊」時，答案可能過時或編造。
希望：**需要事實根據的問題，先上網搜尋、根據搜到的資料回答**。

## 目標
1. AI 對話新增 `web_search` 工具：模型判斷「這題需要最新／事實資訊」就先搜尋，
   根據結果回答（用使用者的語言），並附上簡短來源。
2. 閒聊、翻譯、既有工具能處理的問題（天氣/台鐵/匯率…）**不搜尋**（省時省額度）。
3. 維持**零新增金鑰**優先（家人用的是免費方案）。

## 範圍（要做）

### F1 搜尋來源（架構師實測擇一，關鍵風險）
候選（都用現有資源、不加新付費服務）：
- **A. Groq 內建聯網模型**（`groq/compound` / `groq/compound-mini`，內建 web search）：
  同一把 GROQ_API_KEY、免費方案可用？回應是否含搜尋結果／引用來源？
  延遲多少？→ **架構師必須用 .env 真金鑰實測**。
- **B. DuckDuckGo 免金鑰端點**（lite/html 版擷取）：零金鑰但屬於擷取、脆弱且可能被雲端 IP 擋。
- 兩者都不可行才考慮需註冊的免費層（如 Tavily free）——**最後手段**，要跟使用者說明。

### F2 `web_search` AI 工具（tools.js + 新 service）
- `src/services/webSearch.js`：`search(query)` → 純文字摘要（含 2–3 條來源標題+網址），
  逾時（8–10s）／失敗回 null；快取相同 query（如 10 分鐘）避免重複燒額度。
- `tools.js` 新工具 `web_search`：description 講清楚**何時用**（時事、新聞、價格、產品、
  人物、醫藥、模型不確定的事實）與**何時不用**（閒聊、創意、翻譯、已有專屬工具的查詢）。
- 工具失敗（回 null）→ 回給模型「search unavailable, answer from your knowledge and say so」
  —— **搜尋掛掉不能讓聊天跟著掛**。

### F3 系統提示更新（ai.js SYSTEM_PROMPT）
- 指示：事實性／時效性問題**先呼叫 web_search 再回答**，答案要以搜尋結果為準；
  回答末尾用一行標註來源（域名即可）；搜尋結果與使用者語言不同時，仍用使用者的語言回答。
- 保留既有規則（語言跟隨、簡潔、工具優先序）。

## 不做（範圍外）
- 不做每句必搜（延遲/額度不允許，且多數訊息不需要）。
- 不做多輪深度研究/爬全文（一次搜尋、取摘要即可）。
- 不動既有確定性路由（關鍵字指令、Rich Menu 按鈕、台鐵/加油站等流程）。

## 驗收條件（可測）
1. **搜尋服務**：`search('台積電 是哪一年成立')` 類事實查詢回非空字串且含來源網址；
   斷網／逾時模擬 → 回 null 不丟例外；同 query 第二次走快取（可用計數驗證）。
2. **工具接線**：`tools.run(uid,'web_search','{"query":"..."}')` 回搜尋摘要；
   搜尋 null 時回含 "unavailable" 的英文字串（模型可據此轉述）。
3. **端到端（真 Groq）**：問一題**模型訓練截止後**或明顯需要即時資料的問題
   （例：「2026年7月 台灣 最近有什麼大新聞」）→ 模型呼叫 web_search（可由工具計數證明）
   且回答內容引用搜尋結果；越南語問法亦觸發並以越南語回答。
4. **不誤觸**：「你好」「講個笑話」「翻譯 越南語 謝謝」→ **不**呼叫 web_search（計數=0）；
   「天氣 台北市」等關鍵字路由完全不經 AI。
5. **容錯**：web_search 強制回 null 時，聊天仍正常回答（不 crash、不回錯誤句）。
6. `node --check` 全變更檔；既有功能不回歸。
