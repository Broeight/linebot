## Major：壞資料炸掉整份生日清單

`list()` 的型別判斷是「有 `md` 走國曆、否則當農曆」，農曆分支把 `b.lm` 直接餵進
`nextSolarForLunar()` 的 `lm.split('-')`。手動注入 `{lm:null}` 或 md/lm 皆缺的紀錄
→ TypeError → 整份「生日清單」回覆失敗（index.js 兜底回「發生了一點問題」）。

**緩解脈絡**：指令路徑（`addLunar` 有驗證）永遠寫入合法值，只有手改 `birthdays.json`／
雲端資料損毀才觸發；且改動前的舊版對缺 `md` 的紀錄同樣會炸（`daysUntil(undefined)`），
**非本輪新回歸**——但驗收 11 有防禦條款，一併治好。

**修法**：新增 `isValidLm(lm)` 格式守門（`/^\d{2}-\d{2}$/` ＋月 1-12、日 1-30 範圍檢查）：
- `list()`：壞筆標 `kind:'bad'` 沉底，顯示「（生日資料異常，請刪除後重新記錄）」，
  不拋例外、不中斷其他筆。
- `todays()`：`b.lm != null` 升級為 `isValidLm(b.lm)`，壞資料不命中。

範圍檢查順帶蓋掉獵人的兩個 minor：`{lm:'13-40'}` 原本會被引擎靜默映射成隔年正月
＋日溢位、顯示捏造日期「今年＝國曆 03-17」；`{lm:'ab-cd'}` 原本顯示 NaN 行。
兩者現在都走異常行。
