# PRD — 越南語無障礙第 3 輪：早安推播本地化＋首次歡迎＋台鐵車種翻譯

## 背景
第 1、2 輪後，錯誤訊息/選單/直達/Rich Menu 都已多語化。剩三個缺口：
1. **早安推播**內容全中文寫死（問候語、生日行），vi 訂閱者收到看不懂；且 vi 使用者
   沒有辦法用越南語開關訂閱（指令只有中文「開啟早安」）。
2. **首次接觸零引導**：越南使用者第一次傳訊息，bot 只回答問題本身，她不知道能打
   `trợ giúp`、不知道下面有選單。
3. **台鐵班次的車種**（區間/自強…）對 vi 使用者仍是中文。

## 範圍（要做）

### F1 早安推播本地化
- **問候語**：依訂閱者語言（lang.resolve）出六語問候（zh-TW 維持現有 3 句隨機、逐字不變；
  vi/en 各寫 2–3 句隨機；ja/th/id 回落 en）。
- **天氣段**：zh-TW 訂閱者維持原樣（**不呼叫 AI**）；非 zh 訂閱者將天氣文字用 `ai.ask`
  翻譯成其語言，**翻譯失敗（AI 掛/超時）就回退原中文**，推播照送不中斷。
- **生日行**：模板六語化（名字保留原文）。
- **訂閱確認/取消訊息**：六語化（zh 逐字不變）。
- **vi 開關直達**：`bật tin sáng`／`bật bản tin sáng` → 訂閱（城市預設台北市）；
  `tắt tin sáng`／`tắt bản tin sáng` → 取消。中文指令行為不變。

### F2 越南語首次歡迎（onboarding）
- 使用者語言**首次**確定為 vi（自動偵測或手動切換）→ **主動 push 一則越南語歡迎**：
  簡短 3–4 行（可以用越南語文字/語音跟我說話；打 `trợ giúp` 看全部功能；下方有選單按鈕 👇）。
- **只送一次**：以 `data/lang.json` 使用者記錄裡的 `welcomed` 旗標去重。
- 不影響該則訊息的正常回覆（歡迎用獨立 push、fire-and-forget，回覆先送）。
- **已知限制（接受並記錄）**：Render 磁碟 ephemeral，redeploy 後旗標歸零，她的下一則訊息
  會再收到一次歡迎（訊息短、無害；待未來 DB 遷移後自然變成真正只送一次）。
- 僅 vi（其他語言不送）。

### F3 台鐵車種翻譯（點按鈕後結果）
- `getTraTrainByIds`：`code !== 'zh-TW'` 時，班次行的車種改用 PTX 的英文車種名
  （`typeEn`，如 Local Train / Tze-Chiang Express；缺英文名回退中文）。zh 輸出逐字不變。

## 不做（範圍外）
- 早安推播的 vi 指定城市參數（城市地名 geocode 越南語不可靠，先固定預設台北市；
  之後可用「語言 越南語＋中文城市」繞過）。
- 其他語言（en/ja/th/id）的 onboarding 歡迎。
- 天氣服務本身的全文多語化（維持 AI 翻譯方案）。

## 驗收條件（可測）
1. **zh 訂閱者逐字不回歸**：問候語 ∈ 現有 3 句、天氣段原樣（過程中**不得呼叫 ai.ask**，
   以 monkeypatch 計數驗證）、生日行原句、訂閱/取消確認原句。
2. **vi 訂閱者**：問候語為 vi、天氣段經 `ai.ask` 翻譯（monkeypatch 驗證有呼叫且輸出含其回傳值）、
   生日行 vi 模板。
3. **翻譯容錯**：`ai.ask` 丟例外或回空 → 天氣段回退原中文、整則訊息仍組成並可送出。
4. **vi 開關**：`bật tin sáng` → 訂閱成功且確認訊息為 vi；`tắt tin sáng` → 取消、vi 確認。
   中文「開啟早安 高雄市」／「關閉早安」不回歸。
5. **onboarding**：vi 使用者第一則訊息 → 恰一次 welcome push（stub client 驗證）、
   `data/lang.json` 記錄 `welcomed`；第二則訊息不再 push；zh 使用者永不 push；
   welcome 內容含 `trợ giúp` 與選單提示。
6. **車種**：`getTraTrainByIds({...code:'vi'})` 班次行含英文車種（如 `Local`／`Express`）；
   不傳 code 逐字維持中文車種。
7. `node --check` 全變更檔；既有功能（提醒排程、台鐵、加油站、聊天）不回歸。
