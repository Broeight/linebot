# 追加修正 — 防災警報洗版（2026-07-06 真實使用者回報）

## 問題
使用者訂閱「開啟警報」後，收到一連串**高溫特報**與**淹水警戒**（水利署逐鄉鎮發），
還混入 7/2~7/3 早已過期的舊警報 → 疲勞轟炸，使用者「關閉警報」並回報「都在亂發」。

## 根因
1. `PUSH_CATEGORIES` 白名單留太寬，收了夏天每小時重發的 **高溫、淹水、大雨、降雨、強風**
   （架構師原本就標記過高溫「一下午重發 5 次」，但實作仍收進白名單）。
2. `expires` 只用在 state 修剪，**沒有在推播前擋掉已過期的警報**。

## 修法（`src/services/disasterAlert.js`）
1. `PUSH_CATEGORIES` 縮到只剩「需要立刻反應且相對少見」的 5 類：
   **地震、颱風、海嘯、豪雨（最高降雨等級）、土石流**。移除 大雨/降雨/淹水/高溫/強風。
2. `parseAlerts` 新增過期過濾：`expires` 能明確解析且早於現在 → 略過（防禦性：解析不出或沒填就保留）。

## 驗證（離線對照）
- 混合樣本（5 緊急未過期 + 高溫/淹水/大雨/強風洗版 + 1 過期地震）→ 只留 5 個緊急未過期，其餘全砍。
- 空／亂碼 `expires` → 保留（不誤砍）。
- 壞輸入（null／截斷 JSON）→ 回 `[]` 不 throw。
- `node --check` 通過。既有去重／首次不回補／翻譯安全邏輯不動。

## 備註
若日後家人希望颱風季也收「淹水」，把 `'淹水': 'high'` 加回白名單即可（一行）。
