# PRD — 讓 web_search 更保守（只在需要即時資訊時才聯網）

## 背景
線上實測發現：越南家人問「孕婦能不能擦防曬」（醫藥常識）時，bot 觸發了「上網查證」流程，
一題連打數個大型 Groq 請求（主模型＋聯網搜尋＋再回主模型，每次夾 14 個工具定義＋長對話），
瞬間衝破免費方案的每分鐘 token 上限（~12k TPM）→ 429 → 回保底錯誤訊息。
另也觀察到「推薦電影」被誤觸搜尋、只回「來源：xxx」沒內容的壞回覆。

## 目標
web_search 只在「真的需要最新／即時、會隨時間改變的資訊」時觸發；一般知識、醫藥/健康常識、
推薦、產品/人物介紹、閒聊、翻譯，一律用模型知識或既有工具直接回答，不搜尋。
→ 消除這類問題的 token 爆量與限流錯誤，順帶修掉「只回來源沒內容」的誤觸。

## 變更（僅提示詞，無邏輯/架構變動）
- `src/ai.js` SYSTEM_PROMPT：把 web_search 觸發條件從「新聞/時事/價格/產品/人物/醫藥/不確定知識」
  收斂為「今天新聞時事、最近剛發生的事、目前股價匯率行情、賽事比分、剛上市/發布的即時消息」；
  明列醫藥常識/推薦/一般知識直接答不搜尋。
- `src/tools.js` `web_search` 工具 description ＋ `timeContext()` 句：同步收斂。
- 保留既有規則：搜尋時仍須先寫 2～4 句正文再標來源（防「只回來源」）；每則訊息最多搜 1 次。

## 驗收（RD#4 用真實 Groq ai.chat + runTool 間諜計數）
1. **不該搜尋（web_search 計數 = 0）**：
   - 醫藥/健康常識：「孕婦可以擦防曬嗎」「感冒可以吃什麼」
   - 推薦/創意：「推薦一部電影」「幫我想個晚餐」
   - 一般知識：「珠穆朗瑪峰多高」「番茄炒蛋怎麼做」
   - 閒聊：「你好」
2. **應該搜尋（web_search 計數 ≥ 1）**：
   - 明確即時：「今天台灣有什麼新聞」「現在台積電股價多少」（或類似當前行情/時事題）
3. **不回歸**：專屬工具照走（「台北天氣」→get_weather、「油價」→關鍵字、越南語設提醒→set_reminder），
   不因本次改動誤觸 web_search 或壞掉。
4. 有搜尋的回覆仍含正文＋來源行（非只有來源）。
5. `node --check` ai.js/tools.js 通過。

> 註：LLM 觸發判斷本質為機率性；驗收允許少量偏差，但「醫藥/推薦/一般知識 = 0 搜尋」應穩定達成，
> 「明確即時題 ≥1 搜尋」應達成。若某題邊界模糊（如泛稱「XX 好不好」），記錄實際行為即可。
