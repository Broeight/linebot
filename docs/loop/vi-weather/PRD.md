# PRD — 修復天氣查詢地名解析（越南語地名失敗 + 中文短名默默給錯地方）

## 背景（真實回報 2026-07-02 截圖）
陳氏梅打字「Thời tiết tân trúc ngày mai」與語音「Thời tiết tận chúc ngày mai có mưa không」
都得到「找不到 Tân Trúc 的天氣」。

## 根因（已用真實 API 實測）
天氣服務用 Open-Meteo 免費地理編碼把地名轉經緯度，實測發現它對台灣地名**極不可靠**：
- `Tân Trúc` → 命中**越南**同名村落（16.8°N，錯國家）
- `新竹`（不帶市）→ 命中**屏東**某地（22.46°N，錯地方）；`高雄` → 命中**中國四川**（31.37°N）
- `台北`／`台中`／`桃園` → 查無（現有 +市/縣 fallback 只救回部分）
- 英文名（Hsinchu/Taipei/Kaohsiung/Zhongli…）→ **全部正確**
即：越南語查不到只是冰山一角，**中文短名會默默回錯誤地點的天氣**（更危險，使用者不會發現）。

## 目標
台灣主要城市地名——中文（帶不帶市/縣）、英文、越南語（含語音走音）——一律解析到
**正確的內建經緯度**；非台灣地名（如 Hà Nội，家人會查越南天氣）維持原地理編碼路徑。

## 範圍（要做）
### F1 內建台灣主要城市表（weather.js）
`{ 中文名 → { lat, lon, en } }`，至少涵蓋：基隆、台北、新北、板橋、桃園、中壢、新竹、竹北、
苗栗、台中、彰化、南投、斗六、嘉義、台南、高雄、屏東、宜蘭、花蓮、台東、澎湖、金門。
經緯度用市政府/市中心座標（寫死常數，零外部依賴）。

### F2 統一地名解析 `resolvePlace(name)`（getWeather 與 getForecastSummary 共用）
解析順序：
1. 正規化：trim、`臺→台`、去尾「市/縣」後查中文表。
2. 越南語別名（漢越音，去聲調小寫）：直查 → 去空白 → **模糊容錯（Levenshtein ≤2，表小成本低）**
   → 中文名 → 表。（例：`tan truc`→新竹；語音走音 `tan chuc` 距離 2 → 新竹。）
   別名可重用/擴充 traTrain 已匯出的 `VN_ALIAS`＋補「非車站」城市（新北、屏東…若漢越音明確）。
3. 英文名（表內 `en` 欄，不分大小寫）：`hsinchu`→新竹。
4. 都沒中 → 走既有 geocode 鏈（原名 → +市 → +縣），**行為不變**（保留查越南/世界城市能力）。
表命中回 `{ name（中文）, latitude, longitude, source:'builtin' }`，供輸出顯示。

### F3 AI 工具說明修正（tools.js）
`get_weather` 的 `location` 說明改為：**直接傳使用者原話的地名**（中／英／越南語皆可），
**不要自行音譯或翻譯**，系統會解析——與台鐵工具同一課（AI 亂音譯是上次火車 bug 的主因）。

## 不做（範圍外）
- 不做全台鄉鎮區級完整表（22 個主要城市已覆蓋家人使用場景）。
- 不改天氣資料來源與輸出格式。
- 不動非天氣的地名解析（台鐵有自己的站表）。

## 驗收條件（可測）
1. **resolvePlace 純解析**（不打天氣 API，可離線或僅 geocode fallback 需網）：
   - `新竹`／`新竹市`／`Hsinchu`／`tân trúc`／`Tân Trúc`／`tan truc` → 全部 → 新竹（24.80, 120.97 ±0.1）
   - **語音走音**：`tận chúc`（→`tan chuc`）→ 新竹（模糊容錯）
   - `台北`／`臺北`／`Taipei`／`đài bắc` → 台北（25.04 ±0.1）；`高雄`→高雄（22.6，**不是** 31.x）；
     `台中`／`桃園`／`中壢` → 各自正確座標
   - 非台灣：`Hà Nội` → geocode 路徑命中越南河內（21.0 ±0.3）；亂碼 `zzzz` → null
2. **端到端**：`getForecastSummary('tân trúc')` 非 null 且 Location 含「新竹」；
   `getWeather('新竹')` 回新竹天氣（📍 含新竹、不再是屏東座標）。
3. **工具說明**：`tools.js` get_weather location 說明含「原話/不要音譯」語意；grep 無舊句。
4. **zh 不回歸**：`天氣 台北市` 正常；`天氣 東京` 等外國城市仍可查。
5. `node --check` 變更檔全過。
